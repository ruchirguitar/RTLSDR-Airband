What is this?

      
A local web app for running RTLSDR-Airband as a frequency recorder: add any frequency as a card (not just repeaters — any AM or NFM signal within range), listen to it live in your browser, and browse what got recorded. One SDR dongle, tuned to one center frequency, listens to everything below that fits in its bandwidth.

    


    

      
Receiver settings

      

        
Device index

        
Which physical RTL-SDR dongle to use, if more than one is plugged in. 0 = the first one found. One dongle only? Leave it at 0.

        
Gain · dB

        
Receiver amplification. Higher isn't always better — too high adds noise/overload distortion, too low buries weak signals. 20–40 dB is a common starting range; adjust by ear.

        
Center frequency · MHz

        
Where the dongle actually tunes. Every frequency you add must fall within roughly ±1.2 MHz of this (the receiver's usable bandwidth, a bit less reliable near the edges) — pick a center frequency in the middle of the spread of frequencies you want to monitor. Two frequencies 2 MHz apart won't both fit; you'd need a second dongle.

        
Correction · ppm

        
Crystal frequency correction for your specific dongle, in parts per million. 0 is fine to start; if received frequencies sound consistently offset, look up your dongle's calibration (e.g. via kalibrate-rtl) and set it here.

      

    


    

      
Per-frequency settings

      

        
Modulation

        
NFM for FM voice (most VHF/UHF repeaters and simplex). AM for AM voice (e.g. aviation band). Leaving it unset defaults to AM (the engine's own default) — the Repeaters tab shows this truthfully rather than silently picking one for you.

        
Squelch level (0–9)

        
Just like the SQL knob on a handheld radio. 0 = always open (you hear noise between transmissions too). Higher = requires a stronger signal to open. 5 is close to the engine's own built-in default. If you're missing weak signals, lower it; if it's constantly open on noise, raise it.

        
Record to file vs. Stream to Icecast

        
Record to file saves an audio clip each time squelch opens, into dated subfolders. Stream to Icecast sends live audio to an Icecast server (e.g. for LiveATC-style public streaming) instead of saving locally.

        
Enable live listening

        
Lets you click "Listen live" and hear that frequency in your browser in real time, in addition to whatever it's already recording/streaming. Needs Save + Restart to take effect (it adds a new output to the config, and the engine only reads config at startup).

      

    


    

      
Live listening & sample rate

      
Live audio is carried over a local UDP connection from the engine to this GUI, then played in your browser via Web Audio — so there's a short buffering delay, not zero-latency audio. One setting has to match your build: Live audio sample rate (Process Control tab) should be 16000 if RTLSDR-Airband was built with -DNFM=ON, or 8000 for an AM-only build. If live audio sounds sped up, slowed down, or pitch-shifted, this is almost always why.

    


    

      
Recordings

      
Files are named with the frequency first (e.g. 145.400_MyRepeater_...) so they're easy to identify at a glance in a file browser. Open folder opens the recordings directory in the file manager of whichever machine is running this GUI — only useful when that's the machine you're physically looking at. Delete permanently removes a clip; there's a confirmation, and there is no undo.

    


    

      
Why isn't there a waterfall / spectrum display?

      
The engine only outputs demodulated audio today, nothing exposes raw spectrum data, and a single RTL-SDR can't be shared with a second process to get one another way. Adding a waterfall means adding a new capability to the C++ engine itself, not just this GUI — a bigger, separate project. See the wiki for more.
